# 정치·시사 커뮤니티 여론 모니터링 시스템 (POLI-RADAR)

시사·정치 커뮤니티(**잇싸, 보배드림, 더쿠, 딴지일보**)의 인기 게시판을 요청 시점에 수집해,
정치 현안별로 각 커뮤니티의 반응(스탠스·감성 지수·요약·키워드)을 교차 비교하는 웹 애플리케이션입니다.

---

## 🏛️ 모니터링 대상

| 커뮤니티 | 게시판 | 주 이용자층 | 성향 |
| :--- | :--- | :--- | :--- |
| **잇싸 (ITSSA)** | 정치 HOT | 3050 고관여 | 친민주 / 이동형TV 팬덤 |
| **보배드림** | 정치 게시판 | 3050 남성 | 진보 / 야당 우호 |
| **더쿠** | 스퀘어 정치 카테고리 | 2030 여성 | 중도진보 / 사안별 실용 |
| **딴지일보** | 자유게시판 HOT/HOTBEST | 4050 고관여 | 친민주 / 김어준 팬덤 |

### 제외된 커뮤니티

**에펨코리아**와 **다모앙**은 수집 대상에서 제외했습니다.

- **에펨코리아**: `robots.txt` 가 `User-agent: *` 에 대해 `Disallow: /` 이고, 허용 경로는
  `/$`, `/best`, `/best2`, `/humor` 뿐입니다. `/politics` 는 모든 봇에 명시적으로 금지되어 있으며,
  자체 "보안 시스템"이 루트를 포함해 HTTP 430 으로 차단합니다.
- **다모앙**: `robots.txt` 는 허용하지만(단 `?page=` 페이지네이션은 금지) Cloudflare Turnstile
  챌린지가 걸립니다. 공식 RSS(`/rss`)는 열리지만 공감게시판(`/empathy`) 글이 포함되지 않아
  대체 경로가 되지 못합니다.

두 사이트 모두 명시적으로 자동 수집을 거부하고 있어 우회하지 않습니다.

## 🚀 동작 방식

1. **최초 진입** — "무엇이 이슈인가?" 타이틀과 새로고침 버튼만 표시합니다. 자동 수집은 하지 않습니다.
2. **'인기글 실시간 새로고침' 클릭** — 그 시점 기준으로 4개 커뮤니티를 병렬 수집합니다.
   각 게시판에서 **공지·고정글을 제외한 최신 30개**를 게시물 번호 내림차순으로 가져옵니다.
3. **진행 표시** — 커뮤니티별 수집 상태(수집 중/완료/실패)를 실시간으로 보여주고,
   수집이 끝나면 '핫이슈 분석 중' 으로 넘어갑니다.
4. **리포트** — 현안별로 각 커뮤니티의 스탠스·감성 지수·요약·키워드·대표 게시글을 비교합니다.
   일부 커뮤니티 수집이 실패하면 리포트 상단에 어디가 빠졌는지 표시합니다.

### 서버에 상태를 두지 않습니다

브라우저가 커뮤니티마다 `GET /api/collect` 를 따로 호출하고, 모은 게시물을 `POST /api/analyze`
로 넘겨 리포트를 받습니다. 진행 상황은 4개 요청의 완료 여부로 브라우저가 직접 판단하므로
폴링도, 서버 측 작업 큐도, 데이터베이스도 필요 없습니다.

서버리스(Vercel)에서는 요청마다 다른 인스턴스로 갈 수 있어 프로세스 메모리의 작업 상태나
`/tmp` 의 SQLite 를 다음 요청에서 다시 읽을 수 없습니다. 이 구조는 그 문제를 원천적으로 피합니다.
대신 **수집 이력은 보관하지 않습니다** — 새로고침할 때마다 그 시점의 여론만 봅니다.

### 분석 엔진

- **Claude** (`ANTHROPIC_API_KEY` 설정 시): `claude-opus-4-8` 로 수집된 실제 게시글 제목·반응
  수치를 근거로 현안을 추출합니다. 프롬프트에는 커뮤니티당 반응 상위 18개를 넣고,
  structured outputs(`output_config.format`)로 응답 스키마를 강제합니다.
- **휴리스틱 폴백** (키가 없거나 호출 실패 시): 제목 토큰 빈도와 조회/추천/댓글 수치만으로 집계합니다.
  여론에 대한 해석을 창작하지 않고 관측된 사실만 출력하며, UI 에 폴백 사용 사실과 사유를 표시합니다.

호출이 실패하면(키 없음·인증 오류·사용량 한도·타임아웃) 자동으로 휴리스틱으로 내려가고,
화면 상단에 그 사실과 사유가 표시됩니다.

## 🛠️ 실행 방법

### 백엔드 (API + 정적 웹 서빙)
```bash
cd backend && python run.py
```
> `http://localhost:8000` 접속 시 통합 대시보드가 열립니다.

### 프론트엔드 개발 서버 (옵션)
```bash
cd frontend && npm run dev
```
> `http://localhost:5173` (8000번 백엔드로 프록시)

### 환경 변수
```env
ANTHROPIC_API_KEY=sk-ant-...
```

## 📡 API

| 메서드 | 경로 | 설명 |
| :--- | :--- | :--- |
| `GET` | `/api/communities` | 모니터링 대상 목록 |
| `GET` | `/api/collect?community=<id>` | 커뮤니티 한 곳 수집 (공지 제외 최신 30개) |
| `POST` | `/api/analyze` | 전달받은 게시물로 현안 분석 |

`/api/collect` 는 커뮤니티마다 따로 호출합니다. 한 곳이 실패하면 그 요청만 502 를 반환하고
나머지 커뮤니티는 정상 진행됩니다.

## ⚠️ 알려진 제약

- **잇싸는 Vercel 배포본에서 수집되지 않습니다.** 잇싸가 데이터센터 IP 를 차단해
  `HTTP 403` 을 돌려줍니다. 함수 리전을 서울(`icn1`)로 옮겨도 동일했고
  (`X-Vercel-Id: icn1::icn1` 로 적용 확인), 해외 IP 가 아니라 클라우드 IP 자체를
  막는 것으로 보입니다. 잇싸 `robots.txt` 는 `/hot_politics` 수집을 허용하지만
  인프라 레벨에서 거부하므로 우회하지 않습니다.
  로컬(가정용 회선)에서는 정상 수집되며, 배포본은 나머지 3개 커뮤니티로 동작하고
  리포트 상단에 잇싸가 빠졌음을 표시합니다.
  `icn1` 리전 설정은 나머지 3개 사이트와 한국 사용자에 대한 지연 이점이 있어 유지합니다.

- **수집 이력을 저장하지 않습니다.** 서버가 상태를 갖지 않는 대신, 과거 시점과 비교하는 기능은
  없습니다. 이력이 필요하면 외부 저장소(Vercel Marketplace 의 Postgres 등)를 붙여야 합니다.
- **게시 시각을 수집하지 않습니다.** 목록에 `3일 전 23:39` 같은 상대 시각으로만 노출하는
  사이트가 있어 신뢰할 수 없기 때문입니다. 최신순 정렬은 게시물 번호를 기준으로 합니다.
- **휴리스틱 분석에는 형태소 분석기를 쓰지 않습니다.** 어절에서 조사·활용형만 떼어내므로
  키워드에 잡음이 섞일 수 있고, 감성 점수는 소규모 감성어 사전 기반이라 반어·인용을 구분하지 못합니다.
- **`/api/analyze` 는 공개 엔드포인트**입니다. 게시물을 클라이언트에서 받아 Claude API 로 보내므로,
  공개 배포 시 제3자가 호출해 API 사용료를 발생시킬 수 있습니다.
  길이·건수 제한은 걸어 두었지만, 필요하면 Vercel BotID 나 인증을 추가하세요.
